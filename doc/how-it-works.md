# How better_internet_connectivity_checker works

The parts, and what each seam between them promises. The reasons live in
[`APPENDIX.md`](../APPENDIX.md). Change a seam, change its row.

## The parts

| Part                                                                     | Its job                                                                                                          |
|--------------------------------------------------------------------------|------------------------------------------------------------------------------------------------------------------|
| [`InternetConnection`](../lib/src/internet_connection.dart)              | runs the loop, holds the state, and decides what reaches `onStatusChange`                                        |
| [`ConnectivityProbe`](../lib/src/probe/connectivity_probe.dart)          | checks one target. Yours should honour the `cancelSignal` it gets                                                |
| [`HttpProbe`](../lib/src/probe/transports/http_probe.dart)               | the default. HEAD or GET over a shared client, and it drops its socket when cancelled                            |
| [`_DeadlineProbe`](../lib/src/internal/deadline_probe.dart)              | wraps whatever probe you pass, so none of them can outrun `ProbeTarget.timeout`                                  |
| [`ReachabilityPolicy`](../lib/src/policy/reachability_policy.dart)       | runs the probes, turns their results into one verdict, and stops the ones still going                            |
| [`CheckSchedule`](../lib/src/schedule/check_schedule.dart)               | picks the gap before the next check from a [`ScheduleContext`](../lib/src/schedule/models/schedule_context.dart) |
| [`_PeriodicScheduler`](../lib/src/internal/periodic_scheduler.dart)      | owns the timer. Each gap arrives as the tick's return value, so it never learns what a check is                  |
| [`_EventSink`](../lib/src/internal/event_sink.dart)                      | the lifecycle stream. Built on first read, and delivered a microtask late                                        |
| [`_ExternalTriggerLink`](../lib/src/internal/external_trigger_link.dart) | holds the trigger subscription, and does nothing when there is no trigger                                        |
| [`InternetStatus`](../lib/src/status/internet_status.dart)               | the verdict. `Reachable` with a quality, or `Unreachable` carrying every failure                                 |

## One check, end to end

What a scheduled tick does, in order.

1. The scheduler fires. If the instance is disposed or nothing is listening to `onStatusChange`, it
   stops here and the base interval comes back.
2. `checkOnce()` runs the policy, which puts every target through `_DeadlineProbe`, each capped at
   its own `ProbeTarget.timeout`.
3. The first success wins and the rest get released through `cancelSignal`. If they all fail, the
   verdict is `Unreachable` carrying each failed probe.
4. The listener check runs again, because the check itself took time.
5. `CheckCompletedEvent` goes out, but only when something is listening to `events`.
6. The de-dupe runs. A new status kind reaches `onStatusChange`, preceded by `StatusEmittedEvent`.
   Either way `lastStatus` takes the new value.
7. The failure count goes up on `Unreachable` and back to zero on anything reachable.
8. The schedule reads a `ScheduleContext` and returns the next gap, announced as
   `NextCheckScheduledEvent`. The scheduler waits exactly that long.
